## Reproducible file classification

Run `python3 tools/audit_repository.py`. The generated `.work/v32-audit/repository-inventory.json` records every tracked file's class, rationale, inbound references and build reachability. Classes are CURRENT, HISTORY, GENERATED-REVIEW, REFERENCE and REMOVE. The tool also includes its new source files before their first commit.

The graph scans literal paths, basenames and Python module names from tracked text. Its roots are Make, CI, V32 and audit entry points. CURRENT can mean a **live PRE-V32 dependency**, not architectural authority. HISTORY outside the computed closure is a conservative review candidate, not proof of dead code: dynamic references and unique engineering evidence still need review. No deletion is automated.

Clearly removable tracked files: **none proven in this pass**. Local ignored `__pycache__`/bytecode generated by tests can be removed safely. FreeCAD recovery copies remain ignored engineering evidence. The only exact duplicate groups are the root/package LICENSE and NOTICE.md; these are intentional distribution notices and must remain.
