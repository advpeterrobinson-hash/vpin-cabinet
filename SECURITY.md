# Security and Safety Reporting

## Security vulnerabilities

For vulnerabilities that could enable unauthorized access, malicious code execution, credential exposure, network compromise, or other exploitable behavior, please use GitHub's private security-reporting / Security Advisory mechanism for this repository when available.

Do not publish exploit details in a public issue before maintainers have had a reasonable opportunity to assess the report.

## Physical safety defects

Mechanical, mains-voltage, thermal, fire, structural, and service-safety defects are also important, even when they are not software security vulnerabilities.

For a physical-safety issue that does not create an information-security vulnerability, open a public issue and clearly mark it **SAFETY**. Include only the information needed to reproduce and understand the hazard.

Examples include:

- exposed or reachable mains terminals;
- inadequate protective-earth provisions;
- unsafe playfield support;
- hinge/pivot failure modes;
- leg or cabinet load-path failures;
- pinch/crush hazards;
- overheating or insufficient ventilation;
- inadequate retention of heavy moving components.

## Project status

Engineering files in this repository are not automatically approved for manufacturing. Follow the release status, hardware-freeze gates, proof tests, and warnings in the project documentation.

A source file being public does not mean it has passed prototype or production validation.
